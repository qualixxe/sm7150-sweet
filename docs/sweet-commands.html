A bancada.

Os comandos do port — copiar, colar, rodar. Clique em copy em qualquer bloco. adb = D:\sweet\platform-tools\adb.exe · cel em recovery pro acesso offline ao bloco (MainOS = /dev/block/sda35).

01 — Setup

Conectar e armar a bancada.

Conferir o cel (recovery)

$adb = "D:\sweet\platform-tools\adb.exe"
& $adb devices       # deve listar:  c44c7086   recovery
& $adb get-state

Subir as ntfstools pro /tmp do cel

Nota: o /tmp é RAM — some a cada power-cycle. Re-subir quando o cel reiniciar.

$adb   = "D:\sweet\platform-tools\adb.exe"
$src   = "E:\sweet_drivers\ntfstools"
$tools = 'mkntfs','wimlib-imagex','ntfscp','ntfscat','ntfsfix','ntfsls','ntfsinfo'
foreach ($t in $tools) {
  $p = Join-Path $src $t
  if (Test-Path $p) { & $adb push $p "/tmp/$t" | Out-Null; Write-Host "OK -> $t" }
  else { Write-Host "FALTA: $p" }
}
& $adb shell "chmod 755 /tmp/ntfs* /tmp/mkntfs /tmp/wimlib-imagex; ls -l /tmp/ntfs*"
02 — MainOS

Acessar a partição do Windows.

Montar a MainOS (se o kernel tiver ntfs)

mkdir -p /mnt/win
mount -t ntfs /dev/block/by-name/Windows /mnt/win

Limpar estado sujo da NTFS

Faça antes de ler/escrever se o Windows não fechou limpo (sempre, na prática).

/tmp/ntfsfix /dev/block/sda35
/tmp/ntfsfix -d /dev/block/sda35    # -d = limpa o dirty bit

Listar arquivos (sem montar)

/tmp/ntfsls /dev/block/sda35                                  # raiz
/tmp/ntfsls -l -p /Windows/System32/drivers /dev/block/sda35  # uma pasta
03 — Deploy

Trocar um arquivo no Windows.

Ex.: o driver do touch (.sys)

& $adb push E:\cel\cel\drivers\gtx9886-driver\driver\kmdf\ARM64\Release\vhidmini\vhidmini.sys /tmp
& $adb shell "/tmp/ntfscp /dev/block/sda35 /tmp/vhidmini.sys /Windows/System32/drivers/vhidmini.sys"

Verificar que gravou (hash)

& $adb shell "/tmp/ntfscat /dev/block/sda35 /Windows/System32/drivers/vhidmini.sys > /tmp/back"
& $adb pull /tmp/back E:\cel\back.sys
(Get-FileHash E:\cel\back.sys).Hash   # comparar com o original
04 — Ler o Windows

Investigar offline.

Logs de instalação de driver (setupapi)

/tmp/ntfscat /dev/block/sda35 /Windows/INF/setupapi.dev.log > /tmp/sa.log
grep -ai "GDGT9889" /tmp/sa.log
grep -ai "vhidmini" /tmp/sa.log

Registro (hive SUJO) — hivexsh ignora o "dirty"

O reg load do Windows recusa hive sujo. O hivexsh (WSL, /usr/bin) lê direto.

# extrair o hive SYSTEM pro PC:
& $adb shell "/tmp/ntfscat /dev/block/sda35 /Windows/System32/config/SYSTEM > /tmp/SYS"
& $adb pull /tmp/SYS E:\cel\SYSTEM
# ler no WSL (E: => /mnt/e):
wsl bash -c "printf 'cd \\ControlSet001\\Enum\\ACPI\\QCOM0497\\0\nlsval\n' | hivexsh /mnt/e/cel/SYSTEM"

Event log do Windows (offline, no PC)

& $adb shell "/tmp/ntfscat /dev/block/sda35 /Windows/System32/winevt/Logs/System.evtx > /tmp/S.evtx"
& $adb pull /tmp/S.evtx E:\cel\System.evtx
Get-WinEvent -FilterHashtable @{Path='E:\cel\System.evtx'; Level=2,3} -MaxEvents 50 |
  Select TimeCreated,Id,ProviderName,@{N='Msg';E={($_.Message -split "`r?`n")[0]}} | Format-Table -Auto -Wrap

BCD (boot config) — a ESP é sda34 (FAT)

& $adb shell "mkdir -p /tmp/esp; mount -o ro -t vfat /dev/block/sda34 /tmp/esp"
& $adb pull /tmp/esp/EFI/Microsoft/Boot/BCD E:\cel\BCD_sweet
bcdedit /store E:\cel\BCD_sweet /enum all      # precisa Admin
05 — Build UEFI

Recompilar o firmware.

DSDT → AML + imagem (no WSL)

cd ~/sweet/uefi/edk2-sweet/F11/AcpiTables && iasl DSDT.dsl    # 0 Errors esperado
cd ~/sweet/uefi/edk2-sweet && ./sweetbuild.sh                 # gera sweet_uefi.img -> flash

Decompilar uma DSDT de referência

wsl bash -c "cd /caminho/AcpiTables && iasl -d DSDT.aml"   # gera DSDT.dsl
06 — Drivers / DISM

Injetar drivers na imagem.

Mínimo vs completo (E:\sweet_drivers)

inject_min.bat = só qcgpio+qci2c+touch (atual). inject.bat = moorea completo (PMIC, SPMI, WLAN, Type-C, botões).

DISM manual numa WIM

dism /Mount-Wim /WimFile:F:\install.wim /Index:1 /MountDir:C:\wmount
dism /Image:C:\wmount /Add-Driver /Driver:E:\sweet_drivers\moorea /Recurse /ForceUnsigned
dism /Image:C:\wmount /Get-Drivers /Format:Table        # auditar o que entrou
dism /Unmount-Wim /MountDir:C:\wmount /Commit
07 — Driver do touch

Compilar o vhidmini (WDK).

As 2 flags são obrigatórias: pulam InfVerif e inf2cat. O .sys sai test-assinado mesmo assim.

msbuild "E:\cel\cel\drivers\gtx9886-driver\vhidmini2.sln" `
  /p:Configuration=Release /p:Platform=ARM64 /t:Rebuild `
  /p:SkipPackageVerification=true /p:EnableInf2cat=false
# Saida: ...\driver\kmdf\ARM64\Release\vhidmini.sys
08 — Debug

Quando a serial chegar (KDCOM) / KDNET.

Ligar o debug no BCD (offline, Admin)

Sintaxe: tipo PRIMEIRO, params com :. KDNET-EEM: hostip fixo 169.254.255.255, busparams 1 (DBG2 entry do USB).

bcdedit /store E:\cel\BCD_sweet /dbgsettings NET HOSTIP:169.254.255.255 PORT:50005 KEY:1234.5678.9abc.def0
bcdedit /store E:\cel\BCD_sweet /set "{dbgsettings}" busparams 1
bcdedit /store E:\cel\BCD_sweet /set "{dbgsettings}" dhcp No
bcdedit /store E:\cel\BCD_sweet /set "{default}" debug on
bcdedit /store E:\cel\BCD_sweet /dbgsettings           # conferir

Devolver o BCD pra ESP (rw)

& $adb shell "umount /tmp/esp 2>/dev/null; mount -o rw -t vfat /dev/block/sda34 /tmp/esp"
& $adb push E:\cel\BCD_sweet /tmp/BCD_new
& $adb shell "cp /tmp/BCD_new /tmp/esp/EFI/Microsoft/Boot/BCD; sync"
⚠ Serial 1.8V

A UART de debug do cel (\_SB.UARD @ 0xA88000) é 1.8V. O CP2102/FT232 é 3.3V → use level-shifter (ou o VCCIO do FT232 em 1.8V). NÃO ligue direto — queima o cel.
